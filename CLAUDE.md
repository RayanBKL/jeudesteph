# The Ashtray King — règles du projet

Jeu web satirique 18+ (HTML/CSS/JS vanilla, sans build) : un clicker + jeu de collection de cartes façon Pokémon TCG Pocket, avec casino, bourse, talents et multijoueur. Le joueur aide Stéphane à devenir le roi du cendrier. Interface 100 % en français. État d'avancement, historique et liste des choses à faire : `RECAP.md` (à tenir à jour après chaque grosse session).

## Le but (ce que veut le porteur du projet)
- Un **vrai jeu** qui donne envie de revenir : **rétention**, progression **lente et méritée** (XP, niveaux, points de talent, argent). Ne jamais rendre la progression plus rapide sans le demander.
- Un jeu qui ne fait **pas « généré par IA »** : pas de textes pompeux ou en anglais, pas de doublons (nom répété, titres génériques), pas d'empilement d'emojis décoratifs. Ton direct, familier, drôle.
- **Plusieurs mini-jeux** jouables contre l'ordi ou en multi, avec ligue / classement / prestige par jeu (en cours de conception).

## Règles de design (ne pas casser)
- **Garder chaque élément** existant : on peut tout redessiner, jamais supprimer une fonctionnalité sans accord.
- Direction artistique « bar-tabac PMU » : tons bois/cuir, rouge tabac, jaune doré, papier crème, tapis vert, contours noirs épais + relief. Couleurs via les variables de `css/theme.css` (`--gold`, `--tabac`, `--cream`, `--outline`…), pas de bleus/gris froids.
- Polices : `Cendrier` (police maison, `assets/fonts/cendrier.woff2`, générée par `scripts/build_font.py`) pour titres/montants/boutons ; `Rubik` pour le texte.
- **Aucun écran ne doit faire défiler la page** (mobile 375×667 → PC 1440×900) : chaque écran a la hauteur entre la barre du haut et la barre du bas (`#game-content` fixe). Seules les listes longues défilent dans leur propre zone.
- **Safari** : éviter `aspect-ratio` + `max-width:100%` / `height:100%` dans un parent flex pour dimensionner un élément dont le contenu est en `position:absolute` (taille 0 sous Safari → élément invisible). Donner des tailles explicites ou utiliser `container-type: size` + `cqh/cqw` sur le parent.

## Architecture à connaître
- Ordre des CSS : `style.css` → `empire.css` → `theme.css` (thème + mises en page) → `packs.css` (boutique + ouverture). Les nouvelles règles vont dans `theme.css`/`packs.css`, pas dans les anciens fichiers.
- Après une modif de JS/CSS, **incrémenter `?v=` dans `index.html` et `CURRENT_V`** (cache navigateur).
- Argent : la source de vérité est `ClickerEngine` (`js/clicker.js`). `spendMoney`/`earnMoney` (`js/game.js`) modifient `GameState.money` puis appellent `ClickerEngine.setCash`. **Ne jamais appeler `ClickerEngine.render()` depuis `updateHUD()`** : ça recopie l'ancien solde et annule les débits (bug déjà arrivé).
- Navigation : `showPage()` délègue à `EmpireManager.navigateTo()` (`js/empire.js`) ; un nouvel écran doit y avoir son hook de rendu.
- Cartes : 6037 cartes, image `assets/cards/<préfixe>_<id>.webp`. `node scripts/audit_cards.js` vérifie qu'aucune image ne manque.
- Progression : 1 XP par clic manuel, XP aux paquets (prix/1250, min 15), courbe 300 × 1,35^(niveau−1) ; 1 point de talent par niveau (arbre complet = 46 points).
- **Salle de jeux** (onglet « Jeux », `js/games/`) : `hub.js` (accueil), `league.js` (26 rangs : 8 paliers × 3 divisions + Parrain + Roi du Comptoir, 100 PL par rang, plancher au début du palier), `prestige.js` (défis hebdo façon trophées PS5 : 6 bronze / 3 argent / 1 or tirés au sort, **reset le lundi 0 h**, platine si tout est fait, + prestiges de rang permanents), et un fichier par jeu (`ut.js` Ultimate Comptoir, `quiz.js` Quiz du Comptoir, `bataille.js`, `des421.js`, `pbc.js`, `course.js`). Pour qu'un défi avance, appeler `Prestige.emit('<événement>', {...})`. Les prestiges sont rares et surtout à collectionner (comme les trophées PlayStation) : petite XP, **aucun paquet ni point de talent**. Règles de chaque jeu dans `GameUI.RULES` (`game_ui.js`, bouton « ? »). Contre l'ordi : plafond Buraliste I. **Contre de vrais joueurs** (PBC, 421, Quiz) : `js/games/online.js` + fonctions serveur (`003b_multijoueur.sql`) ; Bataille, Course et Ultimate Comptoir restent contre l'ordi. Les rangs sont dans Supabase (`league_ratings`), le navigateur ne peut pas les modifier ; les prestiges restent locaux (copiés dans la sauvegarde en ligne).
- **Bourse** : `recordSale()` à chaque vente/achat → moyenne mobile des prix (`state.priceHistory`) ; `marketValue(item)` = cote affichée partout (entre ×0,5 et ×2 de la valeur de base) ; indices par famille calculés depuis ces cotes. La revente d'un paquet rapporte ~30-40 % de son prix (pas de boucle d'argent). **Économie** : tout est réglé dans `js/balance.js` (clic de base 12 €, paquets ×40, cote ×40, revenus des cartes rares réduits ; le revenu passif ne vient QUE des cartes placées dans les pièces de l'Empire). Cible : joueur à 1 h/jour = ~40 paquets en 1 semaine, ~300 en 1 mois, ~90 % des cartes en 1 an. Pour retoucher le rythme : changer `PRICE_MULT` puis relancer `node scripts/simulate_economy.js`. Si on change les valeurs, incrémenter `Balance.VERSION` (les anciennes sauvegardes sont converties). Paquet gratuit : 1 toutes les 20 min, 10 en stock.
- **Talents** : 24 talents (arbre complet 66 points) ; points = niveau d'Empire + 1 bonus tous les 5 niveaux (arbre fini vers le niveau 55). Courbe d'XP : ×1,35 par niveau jusqu'au 12, puis ×1,06. Les mini-jeux donnent 30/15/8 XP (victoire/nul/défaite).
- **Cartes** : 10 familles affichées (`tabac` regroupe `cigarette` + `briquet` ; `foot` ; `refs` = **mèmes uniquement** (`scripts/data/memes.json` + entrées `cat: refs` de `refs.json`) ; `chanteur` = Musique (Wikidata/Wikipédia + `refs.json`) ; `culte` = films, télé, humoristes, YouTubeurs, jeux, monuments). Les cartes déplacées gardent leur id d'origine (`ref-…`) et leur image via le champ `img`. **Ne jamais supprimer de carte** (sauvegardes des joueurs). Les footballeurs ont `pos` (GB/DEF/MIL/ATT), `nat`, `clubs`, `ovr` pour l'Ultimate Comptoir (liens vert = club commun, orange = même pays, rouge = rien). Cartes générées : `python3 scripts/build_cards_extra.py` (données Wikidata dans `scripts/data/wikidata/`, listes écrites à la main dans `scripts/data/*.json`) → `js/cards_extra.js` ; images : `python3 scripts/download_extra_images.py` puis `python3 scripts/generate_card_art.py` (dessine une illustration — paquet, briquet, sachet, affiche, phrase de mème — pour toute carte sans photo libre ; aucune carte ne reste sans image) (miniatures via `thumb.wikimedia.org` : `upload.wikimedia.org` et `Special:FilePath` bloquent vite en 429 ; relançable, crédits dans `data/image_credits.json`). Descriptions : ton direct et drôle, en français, pas scientifique.
- **Comptes et serveur** : Supabase (projet dans `.env`, **jamais commité**, jamais dans le code du jeu : seule la clé publique « anon » est dans `js/supabase.js`). `scripts/supabase.sh "<SQL>"` ou `-f fichier.sql` exécute du SQL via l'API de gestion. Migrations dans `supabase/migrations/` (002 comptes/ligues, 003a catalogue, 003b multijoueur, 003c amis/clans, 004 sécurité, 005 anti-triche). `js/account.js` = connexion + sauvegarde en ligne (liste `KEYS` des clés localStorage copiées) ; `js/social.js` = amis, invitations, clans (onglets de la page Profil) ; `js/games/online.js` = recherche d'adversaire et parties en direct. **Règle d'or : le navigateur n'écrit jamais dans une table** (sauf pseudo/photo du profil) ; tout passe par des fonctions SQL `security definer` qui vérifient `auth.uid()`. Toute nouvelle fonction est privée par défaut : `grant execute … to authenticated` explicite.
- **Anti-triche** : la progression (argent, collection) est calculée dans le navigateur, donc le serveur la contrôle à chaque envoi (`cloud_save_put`, `005_anti_triche.sql`) : vitesse de clics, paquets, cartes impossibles → sauvegarde refusée, le jeu recharge la dernière version valide, 3 refus = compte signalé (retiré du classement collectionneurs). `_rl()` limite la fréquence des actions (amis, clans, invitations, sauvegardes). `python3 scripts/backup_db.py` sauvegarde la base dans `backups/` (ignoré par git).
- **Sécurité** : tout texte venant d'un autre joueur (pseudo, nom de clan, photo) est échappé avant d'aller dans `innerHTML` (fonction `esc`), et le serveur impose un format strict (`004_securite.sql`). `.htaccess` : HTTPS, HSTS, CSP, et 404 sur `.git`, `scripts`, `supabase`, `data`, `.env`, `*.md`. `supabase-js` est épinglé avec empreinte SRI dans `index.html`. Passage en ligne : `scripts/go_live.sh`.
- **Dialogues** : jamais de `confirm()`/`prompt()`/`alert()` du navigateur (pas pro) : utiliser `GameDialog.confirm/prompt/alert` (`js/dialog.js`, asynchrone). **Un seul onglet actif** par navigateur (verrou `ak_tab_lock` dans `js/account.js`).
- **Pages** : Profil (`page-profil`, onglets Profil/Amis/Clan) et Réglages (`page-reglages`, ouvert par la roue dentée) sont deux écrans séparés.

## Git : deux branches
- **`main` = la version en ligne** (Hostinger déploie `main`). On ne travaille et on ne commite **jamais directement sur `main`** (elle est protégée : il faut passer par une demande de fusion).
- **`dev` = la branche de travail** : toutes les retouches, bugs et nouveautés se font ici (ou sur une branche courte `fix/…` créée depuis `dev`).
- Pour mettre en ligne : `scripts/publier.sh` (vérifie la syntaxe et les images, pousse `dev`, fusionne dans `main`). Jamais sans que le porteur du projet l'ait demandé.
- Urgence en ligne : créer une branche depuis `main`, corriger, fusionner dans `main` puis refusionner `main` dans `dev`.

## Comment vérifier un changement
1. `python3 -m http.server 8765` dans le dossier du jeu.
2. Tester avec un navigateur automatisé (Playwright + Chromium) en **mobile 390×844 et 375×667** et en **PC 1440×900 et 1440×760**, regarder les captures, vérifier : aucune erreur JS, aucune 404, aucun écran qui dépasse.
3. Pour tout ce qui touche l'argent : vérifier qu'une mise est bien débitée puis créditée, et qu'un clic augmente l'argent affiché.
4. Ne rien commiter sans qu'on le demande. Fermer les serveurs de test (`python3 -m http.server`…) quand on a fini : ils gênent le porteur du projet.
